Lexical Gravity — the standing rail's first widget

Sprint 01 proved the spine on the cheap rail (Spread 01). This widget builds the durable one: commit installs a passage-scoped prose directive that every persona and every mode honors uniformly, consulted only when prose is written. Not attunement, not behavior, not a lens on anyone — a direction the passage's prose should gravitate. And the re-launch semantics flip: standing widgets edit in place instead of clone-and-recommit.

It's interactive: in §1, install a lens via Jill's chip or Widgets. The amber strip that appears above the composer is the live directive — Edit it (shift marker lands in the thread) or kill it with one click. In the panel: the word field, gradient, and substitution tabs are deterministic and instant; Preview the pull and Build lens are the model calls. Try building the falconry lens — it saves to the project.

What this frame decides
  • The active directive is always visible — an amber strip docked with the composer, not buried in a menu. You always know what's pulling on the passage; kill is one click, never a hunt.
  • Amber = standing. Coral marks one-shot commits (Spread 01); amber marks durable passage state. Same coding as the rail badges in the browser.
  • Edit-in-place, not clone. One active directive per family. Editing swaps the standing frame between runs and drops a shifted X → Y marker — the same event class and cache cost as a mode change.
  • Install / shift / kill are thread markers — cheap, visible, auditable history of what was pulling when.
  • Personas propose, never install. Jill's chip prefills the panel; standing state is durable, so it is always writer-committed (the ADR leaning, made concrete).

The pre-commit surface

lens · weight · reach · metaphor pull — scaffold instant, model call explicit

Opened via Jill's chipPhotography · 60% · 2°, pre-preview
Pushed harderMusic · 85% · 3° · substitution view, after Preview
Decisions
  • Config is four values — lens, weight, reach, metaphor pull. Compact enough to persist by stable id, re-hydrate, and diff for the shift marker.
  • The lens is a lexical field, not a word list — separate fields per part of speech (nouns / verbs / modifiers), bucketed by degree of separation. Reach decides how deep the pull reads.
  • Semantic gradient — each lens carries a general → lens gradient (plan → arrangement → composition → score) so weight has a legible meaning: where on the gradient the prose should sit.
  • Substitution view — this lens vs. general vs. a contrast lens (score vs. plan vs. blueprint), so the writer sees the pull as choices, not vibes. Shuffle the contrast column.
  • Everything in the box is deterministic scaffold — instant, free. Preview the pull is the explicit model seam, fast tier, re-rolled on demand; the committed directive never re-runs it.
03

Growing the lens library

look up or invent a lens — model-drafted, writer-picked, project-persisted

Build lens: "falconry"Newtwo drafted takes, pre-pick
Decisions
  • The built-ins are a starter set, not the catalog. Type any domain — the model drafts the full lexical field (POS buckets, gradient, substitutions, metaphor line) as a few takes with details; the writer picks one. Never one silent answer.
  • Chosen lenses persist as project resources (resources/lenses/falconry.json) — compiled once, reusable in every session and thread, editable as a file. Durable truth lives in the project, not the conversation.
  • Writer's-Dictionary-grade knowledge, widget-sized — the dictionary tool already produces lexical-field reports; this reuses that muscle but stores the result instead of re-generating it per session.
  • Building a lens is pre-commit play — drafting and picking touch nothing on the rail. Only Install does.

Invariants
  • Never crosses the persona boundary. No identity, no lens-on-anyone, no mode or expression change. Honored uniformly by every persona and every mode.
  • Coordinator in the WorkshopConversationBehaviorService mold — active-run guard, serialization discipline, changes only between runs.
  • Config persists by stable id host-side; the strip's Edit re-hydrates the exact panel, not a summary.
  • Reserved frame registers with the neutralizer in the same change it ships.
  • Coexists with Prose Controller (Sprint 03) — distinct families, each with its own strip and kill. Precedence under conflict is an open ADR question.
