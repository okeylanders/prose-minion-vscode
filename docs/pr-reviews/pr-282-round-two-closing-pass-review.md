# PR #282: closing-pass review

Reviewed docs-only head `653710112e7b5dd882ca72e4432da89c8bc398c8` against its actual epic base `caff8379`, not main. The product defaults themselves are not defects. Three checklist issues should be fixed before using it as acceptance evidence.

1. **P2 — A3 accidentally tests cached pages rather than cancellation or the distance cap** (live-pass.md:80–105). Steps 2 and 3 load the ~50- and ~250-back bookmarks. Step 6 then asks the tester to start an asynchronous jump to that same ~250-back turn. It is already displayed, so the jump completes immediately; no late reply exists to supersede. Step 4’s ~400-back bookmark may also now be within 300 turns of the oldest loaded page. Reopen the session between cold cases, deliberately retain pages only for the already-loaded case, and use a fixture of at least 600 turns for a target 400 before a 200-turn window. Verify a request really is pending before testing cancellation.
2. **P2 — H7 cannot induce the claimed failure with a warm help reader** (live-pass.md:337–350). Prior H steps load the bundled index. WorkshopHelpReference caches successful loads for the reader’s lifetime; renaming the resource directory then leaves ordinary lookups working from memory. Restore H6’s altered source, rebuild, start a fresh Extension Development Host, rename the staged directory *before* its first lookup, then restore it and retry without restarting. Distinguish resetting before the experiment from preserving the same reader during recovery.
3. **P2 — B leaves memory off for C and D** (live-pass.md:167 onward). The setup selects ask-first, but B6 changes that persistent setting to off. C then expects personas to read memory and D expects note cards, without re-enabling it. Explicitly restore ask-first and start a suitable fresh conversation before C/D, or isolate the scenarios in separate profiles.

**Handoff note:** The decision list includes Q4/Q6 but omits the exact-heading-first ranking default explicitly left for Okey in #279. Carry it forward or point to a subsequent owner decision; this is a documentation gap, not a ranking defect.

**Scope:** Cross-checked the runbook against the reader cache, bookmark paging/cancellation semantics, and persistent Workshop memory mode. No live-model or Extension Development Host run was performed; no runtime code changed. The potential main-branch version mismatch is outside this PR’s base and is not a finding here.
