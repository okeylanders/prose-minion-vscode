# PR #280: Workshop help follow-ups

Reviewed code: `f2745f41cd285fb48c358a7c16caa85f737b7b36`, relative to `3a6054c3`. The retry now works and overlapping callers share the load. Two correctness findings and a copy note:

1. **P2: A term labeled “Not searched” can change the result order.** In WorkshopHelpReference.ts:115–137, the matcher gets the full parsed phrase, but the renderer calls every overflow term ignored. In a direct run against the head with two equally matched sections ending in “iota” and “kappa”, searching “alpha beta gamma delta epsilon zeta eta theta” returned iota then kappa. Appending “kappa” reversed them while listing kappa as ignored. With an eight-hit cutoff, ordering can change what is shown. Either exclude overflow from help phrase scoring or describe the actual term-versus-phrase behavior. Add an ordering-sensitive fixture; keep recall semantics unchanged.
2. **P2: Refusals outside the reader misidentify the reference after a version mismatch.** WorkshopPersonaCapability.ts:1043–1046 calls the installed version the reference version. With installed 2.15.0 and reference 2.14.0, a successful read names 2.14.0 but a malformed or over-limit call claims the reference is 2.15.0. Label only the installed version when no reference version is known, or use the already-loaded reference version. Test success followed by a malformed or over-limit call with unequal versions.
3. **Minor: use a direction-neutral mismatch caveat.** WorkshopHelpCopy.ts:8–12 uses the same wording in both directions. A newer reference can describe controls absent from an older installation; the persona prompt only teaches the older-reference case. A neutral “these versions differ; features or controls may not match” avoids directional assumptions.
