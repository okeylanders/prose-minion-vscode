### F4 · P2 · A competing named edit turns a retryable mirror failure into a permanent close failure

A writes a manuscript edit. Its rolling write temporarily fails, so A uses Save as New: the named file commits, but the rolling mirror still fails. The filesystem recovers. B opens the saved checkpoint in an independent store and commits another edit against the correct baseline. On A's next close, [the mirror checks the named source](https://github.com/okeylanders/prose-minion-vscode/blob/a4e5d97560930a513bad62555082b87baef63d1b/packages/core/src/application/services/workshop/WorkshopSessionPersistenceCoordinator.ts#L573-L615) and correctly refuses to publish A's outdated checkpoint. But the failure is `WorkshopNamedSessionChangedError`, not `WorkshopRollingCheckpointConflictError`. No close destination is recorded. [Close](https://github.com/okeylanders/prose-minion-vscode/blob/a4e5d97560930a513bad62555082b87baef63d1b/packages/core/src/application/services/workshop/WorkshopSessionPersistenceCoordinator.ts#L731-L767) keeps retrying an equality check that cannot succeed by waiting.

I checked this with two real stores and the real coordinator over the project's in-memory filesystem. Two consecutive closes rejected after the I/O failure was removed. A fresh store found only B's manuscript in the named catalog, and the rolling file was still the byte-identical pre-edit checkpoint. A's text remained in the live room; neither close returned an identity from which to reopen it. The error advises reopening the other writer's version, not how to keep A's version. This is not a claim that a rejected close immediately drops the room.

**Fix and acceptance:** On a *confirmed* changed or missing named source for a pending mirror, preserve the owed checkpoint under a fresh, non-overwriting identity, read it back, and return that identity on close. Do not treat an inconclusive read, failed recovery write or transient I/O error as a successful close. Keep the competing named version and prior rolling bytes intact. Add a regression that first fails only the rolling write, lets a second store update the authoritative file, then closes and reopens A's exact text after I/O is healthy. The existing [changed-again test](https://github.com/okeylanders/prose-minion-vscode/blob/a4e5d97560930a513bad62555082b87baef63d1b/packages/core/src/__tests__/application/services/workshop/WorkshopSessionPersistenceIntegration.test.ts#L886-L913) exercises the reverse ordering: a rolling conflict has **already** established a close alternative before the competing rename.
