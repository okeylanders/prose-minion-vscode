## Findings

1. **P2: A withheld project or recall read can still consume the allowance for the retry.** The new admission decision at `packages/core/src/application/services/workshop/WorkshopPersonaCapability.ts:373–379` avoids recording a withheld result as delivered, and memory delivery now charges at settlement. But `WorkshopResourceRead.ts:115–122` and `recall/WorkshopRecallReadOperation.ts:113–118` still charge during preparation. When the live context limit becomes known or shrinks before dispatch, the engine substitutes the short notice but still leaves the withheld project or recall result charged. A real-engine test with a mocked provider and catalog observed a narrower project read refused after the withheld result left only 880 bytes of its allowance. Defer the delivered-body charge until admission while retaining separate attempt limits. Add project and recall cases beside the memory case.
2. **P2: Withholding the first result drops the warning that other native calls in the same reply never ran.** `WorkshopPersonaCapability.ts:365–379,1134–1136` appends the skipped-call warning to normal evidence, but returns the bare overflow notice when that result is withheld. In a multi-call reply, the model no longer learns that the sibling call was never run. Preserve the short host-generated warning on the replacement, and measure the complete replacement before sending it.
