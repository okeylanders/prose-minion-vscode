# PR #301 · Independent Workshop tabs · Design review

**Independent reviewer:** Astra 6.2 | **Verdict:** Request changes to the ADR and sprint gates before integration.

Reviewed `0830be3c` → `6b8d0e76`. The four changed files are Markdown. The split between a durable slot, a loaded room and a panel attachment is sound. Keep host-bound inbound routes, the existing room-replacement checks, and named-session compare-and-swap. These findings concern contracts the implementation will need, not runtime regressions introduced by this PR.

1. **P1 · Protect the scratch writer across extension windows.** D3 (ADR lines 32–34) reserves one `legacy` address and makes other scratch slots discoverable, but the ownership registry is window-local (line 11). Two windows on one workspace can both regard the same slot as closed, including the upgrade slot. The real rolling write replaces with `overwrite: true` without an expected checkpoint; named CAS is a separate path (`packages/core/src/infrastructure/storage/WorkshopSessionStore.ts:209–224,243–256,285–300`). Atomic replacement is not conflict detection. Specify a cross-window claim/fence or private copies with conflict-safe adoption. Include legacy and UUID restore/picker races using two independent registries over the same filesystem: either a second writer is refused or forked, and neither writer's text disappears.

2. **P1 · Close needs a durability result, not just a settled promise.** D3 (line 34; epic sprint 02, line 15) says to flush and expose failures for retry. Today a scratch write failure is caught and reported to listeners, `flush()` retries once and may resolve still dirty, and it does not unconditionally join the separate session-operation queue (`packages/core/src/application/services/workshop/WorkshopSessionPersistenceCoordinator.ts:601–637,1648–1663`). The panel drops its handler on disposal (`apps/vscode-extension/src/application/providers/WorkshopPanelProvider.ts:235–248`). A close can look complete with newer writer data only in memory, or a late operation can write over a reopened slot. Specify a closing state that retains the slot/dirty data and blocks or joins reopen until operations, autosaves and mirrors reach a known outcome; give retry a surviving owner. Test a held session operation and persistent real-store write failure, not only a fake rejecting flush. Verify the old on-disk checkpoint survives, another room drains, and a retry recovers the latest edit.

3. **P2 · Bind the Lightbox receipt and tray as well as the send.** D5 (line 42) fixes the send destination at the gesture. The current handoff port is first called *after* a possible file reread; on a lost acknowledgement, the sender checks a single injected Workshop tray by board/tile ID (`packages/core/src/application/handlers/domain/LightboxHandoffRoute.ts:199–210,243–259,276–278`; `packages/core/src/application/handlers/MessageHandler.ts:398–400`). After focus moves to B, an identical tile in B must not turn A's failed handoff into “staged,” nor should A's successful stage be reported missing. Capture the target before rereading, specify how the visible tray and its Open action select their owner, and reconcile a lost receipt only against the original loaded room or delivery. Extend `LightboxTileHandoff.test.ts:176–216` with A/B, close/reset and an identical tile in B; assert results, not just routing.

4. **P2 · State the persistence boundary for folderless and multi-root windows.** D3 (lines 32–34) promises disk-backed reopen with no workspace precondition. The actual store explicitly refuses both workspace shapes (`packages/core/src/infrastructure/storage/WorkshopSessionStore.ts:209–224`); initialization deliberately keeps Workshop live in memory (`packages/core/src/application/services/workshop/WorkshopSessionPersistenceCoordinator.ts:477–481`), and the window-owned session outlives its panel (`apps/vscode-extension/src/extension.ts:310–313`). Closing a panel must not silently discard the only room copy. Scope cross-restart recovery to supported storage, define same-host close/reopen for ephemeral rooms, and test independent rooms with no folder and two roots. Never select an arbitrary root to make the test pass.

5. **P2 · Decide which usage counter is local, and how to attribute it.** D5 (line 42) calls for usage feedback in the initiating room. But the shared manager sends bare usage to every listener, and each handler increments totals and replaces its last-request price (`packages/core/src/infrastructure/api/orchestration/AIResourceManager.ts:63–75`; `packages/core/src/application/handlers/MessageHandler.ts:232–239,539–568`). Existing `MessageHandler.test.ts:454–482` deliberately asserts multicast. Distinguish account/window totals from a room's run usage; specify an originating-run callback or identifier if that room meter is local. Gate with A and B completing differently priced synthetic runs out of order: room-specific readings stay with their owners while explicitly global readings remain shared.
