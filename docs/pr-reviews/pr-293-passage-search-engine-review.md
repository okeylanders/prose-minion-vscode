# PR #293 review: Passage Search, Slice 1 (engine)

**Astra 6.2 · 2026-11-20 · Changes recommended before merging into `epic/passage-search`.** Reviewed `fcc82ac075e2c2602f54d2c49e051f3f88eb24da` against `e45d8d1bb1e1111b5acd4afbcda8bf3f17166142`. This slice exposes an engine and a settings scope, not a search UI or a live organizer.

## Findings

1. **P1 · Resolve editor scopes from the current editor, not remembered text.** [PassageSearchScopeFiles.ts:178–207](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/application/services/passageSearch/PassageSearchScopeFiles.ts#L178-L207) uses `getActiveSelection()` for both Active file and Selection. [VsCodeEditorContext.ts:95–119](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/apps/vscode-extension/src/platform/vscode/VsCodeEditorContext.ts#L95-L119) can fall back to the last nonempty selection. When the panel takes focus after a selection is cleared or its editor closes, the plan can target the old manuscript instead of the current scope or refusing. Snapshot the current-editor context once before asynchronous scope discovery; if the current editor or selection is absent, refuse rather than substituting another. Cover a formerly selected A, a live B with no selection, and a closed editor.
2. **P1 · Notice key rotation after the final reads were admitted.** [PassageSearchService.ts:180–198](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchService.ts#L180-L198) and [organizer admission](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchService.ts#L230-L239) infer rotation from a later request returning missing credentials. The [engine captures its provider at admission](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/orchestration/AgentRunEngine.ts#L295-L303), and [retirement does not undo in-flight requests](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/orchestration/AIResourceManager.ts#L499-L507). If every read was already admitted, there need not be a later rejection: the run reports complete and can invoke an injected organizer. Capture a credential/provider generation or verify the captured engine identity if it uniquely tracks credentials, after reads settle and immediately before organizer admission. Keep finished results and retain key-changed precedence. Test retirement with exactly four reads in flight and a wired fake organizer. The production organizer is a no-op in Slice 1, so this is not an observed extra charge.
3. **P2 · Do not label dispatched calls `unsent`.** [PassageSearchService.ts:281–299](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchService.ts#L281-L299) increments `unsent` for cancellation, even when the provider returned usage. [AgentRunEngine.ts:946–970](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/orchestration/AgentRunEngine.ts#L946-L970) can return usage and flag the call cancelled. After Stop, the synthetic run showed 10 unsent even though four dispatched calls counted in usage. Separate cancellations after dispatch from never-started work (carry dispatch evidence at the transport boundary if needed); keep usage, and cover four concurrent cancelled responses plus the queued calls.
4. **P2 · Report actual per-file search coverage.** [PassageSearchService.ts:191–209](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchService.ts#L191-L209) exposes the merged file table as `files.read`, but [PassageSearchInstances.ts:135–142](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchInstances.ts#L135-L142) fills it from all planned files. A wholly unsent file looks like an answered zero-hit file, and the caller cannot report partial coverage. Track per-file admitted and successfully answered chunks; expose never searched, partially searched, and fully searched even where there are no hits. Test each state.
5. **P2 · Align the 300-call limit with organizer accounting.** [PassageSearchPlanning.ts:75–85](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchPlanning.ts#L75-L85) checks only read chunks; the [estimate](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchPlanning.ts#L152-L170) later adds the organizer. At 300 reads with an available organizer, the plan accepts 301 total even though ADR D2/D6 and the [refusal copy](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchRefusals.ts#L45-L47) present a 300-call limit. Either reserve the organizer's slot or explicitly decide and document a read-only cap. This only affects the organizer seam until Slice 3.

6. **P2 · Make overlap deduplication deterministic.** [PassageSearchService.ts:312–314](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchService.ts#L312-L314) appends answers in completion order. [PassageSearchInstances.ts:153–162](https://github.com/okeylanders/prose-minion-vscode/blob/fcc82ac075e2c2602f54d2c49e051f3f88eb24da/packages/core/src/infrastructure/api/services/search/passage/PassageSearchInstances.ts#L153-L162) does not break ties when two chunks anchor to the same range. The same plan and two replies kept a different note and label when only the network completion order changed. Break ties by originating chunk index and reply-item order, or document a different deterministic preference. Add a deferred-order test.

**Follow-up before persisting consent keys across upgrades:** consider freezing and hashing the actual output ceiling in the plan as well as the estimate’s typical output tokens. A changed static ceiling can otherwise leave the key unchanged. This is not a price-cap finding.
