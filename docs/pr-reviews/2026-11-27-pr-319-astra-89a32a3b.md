## Findings

1. **P2: A fast second Send can replace the writer's prompt with an attachment-only turn.** In `packages/core/src/presentation/webview/components/workshop/WorkshopComposer.tsx:189–199`, posting a turn clears the local text but leaves Send enabled while the current attachment tray is still visible. A second Enter before the host publishes its running state can submit an empty turn using that tray. The host preempts the first request rather than coalescing it (`packages/core/src/application/handlers/domain/workshop/WorkshopRoomHandler.ts:1232,1747–1755`). Add an immediate pending-send guard scoped to the request, and unlock it on the corresponding host acceptance or refusal. Test two submissions before host acknowledgement.
2. **P2: The character-limit fallback can create a staged body that fails its own saved-state validator.** In `packages/core/src/utils/cutWorkshopAttachmentText.ts:27–32`, an input with substantial leading whitespace and multiple words can take the single-word fallback, restart the cut from trimmed text, and store a word count of one. The cut can then contain multiple words, which the count verifier rejects (`packages/core/src/application/services/workshop/WorkshopPastedText.ts:45–47`). Keep the actual bounded prefix and derive the stored counts from the final body. Test a pad at the character boundary, then round-trip the staged and sent records.
3. **P2: A live Selected Text pill alone cannot be sent from the composer.** The same `WorkshopComposer.tsx:189–195` check only accepts a nonempty draft or the staged attachment collection. The enabled live Selected Text pill is rendered separately, and the host stages it before its empty-message check (`WorkshopRoomHandler.ts:629–638`). Include the eligible live selection in the send predicate, or clearly communicate that it must be staged manually. Test this alongside the pasted-pill-only path.
