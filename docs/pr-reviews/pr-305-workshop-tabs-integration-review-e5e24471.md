### F1 · P2 · A queued context refresh can change attachments after the tab closes

The [new revision check](https://github.com/okeylanders/prose-minion-vscode/blob/e5e244712024ae1f09f88be1ba06c53de4f14cfe/packages/core/src/application/handlers/domain/workshop/WorkshopContextHandler.ts#L271-L315) covers a scan that **starts** before close. The [Refresh command](https://github.com/okeylanders/prose-minion-vscode/blob/e5e244712024ae1f09f88be1ba06c53de4f14cfe/packages/core/src/application/handlers/domain/workshop/WorkshopSessionMessageHandler.ts#L413-L425) can also be waiting for an [earlier autosave](https://github.com/okeylanders/prose-minion-vscode/blob/e5e244712024ae1f09f88be1ba06c53de4f14cfe/packages/core/src/application/services/workshop/WorkshopSessionPersistenceCoordinator.ts#L1777-L1797). If the writer closes during that wait, the [registry already advances the revision](https://github.com/okeylanders/prose-minion-vscode/blob/e5e244712024ae1f09f88be1ba06c53de4f14cfe/apps/vscode-extension/src/application/WorkshopRoomRegistry.ts#L112-L129). When the queue drains, the disposed handler captures the **new** revision as its starting point. Its scan can therefore replace a standing attachment, append a refresh turn and mark the closing room dirty. Suppressing posts to a closed webview does not protect the aggregate.

**Observed:** An offline activation witness attached a file, changed its source, paused a rolling autosave, sent Refresh, closed the panel, then released the autosave. Expected zero further reads or attachment mutations. Observed one further source read and a call into the real attachment mutator with the new contents for `ctx-1`. The shipped close-during-refresh test pauses inside an already-started read, so it passes for both implementations.

**Fix and acceptance:** Check the originating handler’s disposal state before any queued scan starts and again before adopting results or issuing effects. Keep the generation check as well; disposal and replacement are different. Run the queued-close case through the activation route and assert no late attachment change, turn or dirty mark. Cover the automatic session-open scan that shares this helper, and retain the normal hidden-but-not-closed behavior.

### F2 · P2 · The window can show another request’s price as the latest price

The [window accumulator](https://github.com/okeylanders/prose-minion-vscode/blob/e5e244712024ae1f09f88be1ba06c53de4f14cfe/packages/core/src/infrastructure/api/orchestration/AIResourceManager.ts#L69-L85) changes the last price on a usage event with nonzero tokens. A completed streamed or non-streamed response can have no usage object: the [engine suppresses that event](https://github.com/okeylanders/prose-minion-vscode/blob/e5e244712024ae1f09f88be1ba06c53de4f14cfe/packages/core/src/infrastructure/api/orchestration/AgentRunEngine.ts#L1274-L1276). This differs from a usage object that has tokens but omits cost, which already clears the price. The displayed “Last request in this window” and the [message contract](https://github.com/okeylanders/prose-minion-vscode/blob/e5e244712024ae1f09f88be1ba06c53de4f14cfe/packages/core/src/shared/types/messages/configuration.ts#L187-L198) refer to the last completed request, not the last request that reported usage.

**Observed:** A completed with 10 tokens and a synthetic $0.50 price; B then completed with visible prose and no usage metadata. B’s reply was in B’s transcript. A fresh window-usage query from B correctly kept 10 known tokens but incorrectly returned `lastRequestCostUsd: 0.5`. This affects attribution in the UI, not the provider’s actual charge.

**Fix and acceptance:** Distinguish request completion from the presence of measured usage. An unmeasured successful completion clears the last price without adding guessed cost or tokens and without resetting measured totals. Keep activation/reset and pre-dispatch failure separate from request completion. Add this case to the out-of-order two-tab witness, including a late subscriber.
