## Context worth keeping

- **`marked` keeps container lines one for one.** A blockquote's or list
  item's `text` has the same line count as its `raw`, from the first line,
  with prefixes stripped and tabs maybe expanded. Children's raws
  concatenate to the container's `text`. That is what makes line-exact block
  regions possible. Each protected block is still checked line by line, and
  fails closed.
- **Use `new Lexer(getDefaults()).blockTokens(body)`, not `marked.lexer`.**
  The full lexer runs inline tokenization too, which took 3.7 s on 40k
  backticks. Block tokens alone are linear.
- **`marked` blows up on deep nesting:** 5,000 nested quotes overflow the
  stack, and 5,000 nested lists exhaust memory. The guard
  (`MAX_CONTAINER_DEPTH` 32, `MAX_LIST_INDENT` 64, list indentation
  counted inside quotes too) protects such a document whole.
- **`AIResourceManager.refreshConfiguration()` must keep rebuilding
  unconditionally.** Its tests and the Lightbox key retirement rely on it.
  Dedup lives in `AIResourceRefresh`, and the manager is near the 500-line
  limit anyway.
- **App adapter tests can mock `vscode` per file**
  (`apps/vscode-extension/src/__tests__/platform/vscode/draftEditDocumentLifetime.integration.test.ts`):
  `jest.mock('vscode', factory, { virtual: true })` overrides the setup's
  mock.
- **VS Code reuses the same `TextDocument` object across a language change**
  (close then open). A reopen is a new object, with `isClosed` true on the
  old one. The watch uses the close event and `isClosed`, never object
  identity.
