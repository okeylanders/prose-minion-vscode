## How the captures were made

The scratch scripts were not committed (`lib.js`, `room.js`, `host.js`, `capture3.js`, `dict.js`, `compose14.js`, `tour.js`). The method is the v2.13.0 one; see [that record](20261112-1300-release-v2.13.0-docs-tour-and-artwork.md).

- **Workshop states:** one `workshop_session_state` snapshot each, of made-up rooms about *Alice* (public domain).
  - Selected Text: a writer turn whose attachment carries `selectedText`, then the toggle clicked and a `workshop_selected_text_current` answer for the live pill.
  - The read: a `resource_read` capability turn whose summary is the host's own wording for three files.
  - The rail: the header's Side pane button pressed, at a 1000 px window.
  - Re-read: a `file`-kind excerpt and no turns.
- **Dictionary:** the same bundle as the sidebar surface. The stand-in host answers `request_dictionary_history` with eight made-up lookups and `search_dictionary_history` with snippets, request id echoed.
- **No model was called.** The model names shown are demo content.
- **Captures:** 2× crops by element box, 0 page errors, each looked at before use. Composites are 1×, 1252 px wide: 1201, 1747 and 1098 px tall, 198–308 KB.
- **The multi-file card** is shown collapsed, as its one summary row. How it draws per-file rows and a raw continuation line when opened has not been reviewed by eye (the epic says so), so the artwork does not show it.
- **The tour pages** were rendered from the rebuilt bundle at 1240×900 with the real shots: every image loads and every call-out sits on its control.
